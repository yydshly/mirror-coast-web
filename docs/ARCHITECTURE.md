# 项目结构

这是纯浏览器单机应用：静态文件加载后，场景生成、渲染、模拟和保存都在用户浏览器执行。

```text
输入与操作模式
    ↓
main：初始化、控制权、运行帧与系统协调
    ├─ world：32³体素分块、生成、网格Worker、远近景加载
    ├─ input / vehicles：人物、镜头、自行车、汽车、直升机
    ├─ simulation：街道人群、车流和路口通行
    ├─ destruction：伤害、支撑分析、Rapier刚体与废墟
    ├─ rendering / audio：地形附件、环境、海水、天气、声音
    ├─ gameplay / ui：探索、路线、地图、手记和互动反馈
    └─ persistence：版本校验、编辑差量、载具／探索状态、IndexedDB
```

## 重要约束

- 近处编辑的可见网格和碰撞保持一致，不能只删除画面或只删除碰撞。
- Worker返回结果有修订校验；常规网格安装有帧预算。
- 世界状态与场景投影分开考虑，渲染对象和物理句柄不直接写入存档。
- 远景简化只改变显示，实际世界数据和碰撞仍保留。
- 独立旅程使用独立保存位置。导入失败不应覆盖已有有效数据。

建筑形体改造在初始生成后、保存编辑恢复前执行，始终写入权威体素。附件按真实分段的立面生成，不能另用整栋包围盒堵住退台。原建筑所有权索引覆盖新楼体，保留旧存档整栋拆除的有效范围。实现与实测说明见 [BUILDING-MASSING.md](BUILDING-MASSING.md)。

## 发布维护

游戏入口为 `src/main.ts`，样式在 `src/style.css`；部署只需要 `npm run build` 生成的 `dist/`。
该子项目的初始源码来自现有沿海原型。后续修改须明确是在发布子项目还是原工程进行，避免两份代码独立漂移。
